# GloriaSetup rollout for Nothing

Pushing a tag like `v1.2.0` now builds the app, packs it with `projectGloria/GloriaSetup@v0.1.0` and attaches
`Nothing_1.2.0_x64-setup.exe` to that release. Nothing was built or run locally.

## Please

Review these choices, which I made on my own because I could not ask:

1. **The Windows service is not installed by GloriaSetup.** The old `nothing-setup.exe` ran elevated: it installed to
   Program Files, registered the `Nothing Index` service (LocalSystem, needed for the raw MFT and USN journal),
   a logon `Run` entry, Explorer context-menu verbs and the sparse MSIX package. GloriaSetup is per-user and does
   none of that. The new setup only copies the files, so the search service will not exist until the app or setup
   gains a way to register it (for example `nothing.exe --install` run elevated on first launch). Decide before
   you tag a release that replaces the old installer.
2. **Packed files:** `nothing.exe`, `nothing-svc.exe` and `nothing_shell.dll`. `nothing.msix` (the Windows 11 compact
   context-menu package) is only produced inside `crates/setup/build.rs`, so it is not in the setup.
3. **Old installer left in place.** `crates/setup` and `build-installer.cmd` still exist, but the workflow no longer builds
   or publishes `nothing-setup-<tag>.exe`.
4. **Version:** `gloria.toml` says `1.0.0` (workspace `Cargo.toml`); the catalog says 0.2.1. The tag always overrides it
   in the setup, but `Cargo.toml` is not changed by the tag.
5. **Icon:** there is no `Nothing.ico` and no committed `.ico` (the exe icon is generated by `crates/ui/res.rs`). I used
   `assets/icon-256.png`, which is 256x256.
6. **Data folders:** only `%APPDATA%\Nothing` (`settings.ini`). The service's index lives in `%ProgramData%\Nothing`,
   which the manifest does not allow, so uninstall will not remove it.
7. **`legacy_names` is empty.** The old installer was custom, not NSIS/Inno/MSI/Electron-builder, so I did not list
   its `Nothing` uninstall entry for migration. Its HKLM-style entry may remain next to the new one on machines that used it.
8. **Signing** uses the `WINDOWS_PFX_BASE64` and `WINDOWS_PFX_PASSWORD` secrets; if they are not set the setup is unsigned.
